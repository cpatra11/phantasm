# tldraw Board + AI SDK Tool-Loop Agent

## Context

The planned file `/Users/cpun/.opencode/plan/plan.md` is the source of truth (canvas decision confirmed by user Nov 4, 2026). The built app deviates from it in two ways, both now to be aligned:

1. **Board/Editor are DOM/CSS** — plan.md specifies a **tldraw SDK** infinite board with brand cards, prompt cards, and storyboard artifact cards.
2. **Agent is a hand-rolled fixed-order NDJSON pipeline** (`lib/agent/workflow.ts` calling `lib/meta/*` directly) — plan.md specifies a **Vercel AI SDK v5 tool loop** (`generateText` + tools `create_storyboard`, `generate_image`, `segment_subject`, `apply_patch`), with Muse Wonder doing planning inside the agent.

`ai@5.0.285` and `@ai-sdk/openai-compatible@1.0.61` are already installed but unused. Server contracts (NDJSON `AgentEvent`, `/api/artifacts`, `/api/render`, credits, SceneDoc) stay unchanged so `Editor.tsx`, route ownership checks, and credit spend/refund keep working.

## Workstream A — tldraw Board

**Files:** `package.json` (+`tldraw` v3, React 19 compatible), new `components/board/`, rewrite of `components/Board.tsx`, small additions to `app/globals.css`, `app/app/page.tsx`.

1. `npm install tldraw` and import `tldraw/tldraw.css`.
2. **`components/board/TldrawBoard.tsx`** (client, loaded via `next/dynamic` with `ssr: false` — tldraw needs the DOM):
   - Custom shape utils registered via `createShapeUtils`:
     - `brand-card` — renders brand name, source URL, color swatches, fonts (reads BrandKit from shape props; created/updated when `POST /api/brand` resolves).
     - `storyboard` — props `{ artifactId, title, version }`; renders the existing `<PlayerPreview doc aspect="9:16" width={180}>` (components/PlayerPreview.tsx, reused as-is) plus title + version chip. Click → `router.push('/app/${artifactId}')`.
   - `persistenceKey="basix-board"` for free local persistence of positions/zoom.
   - New artifacts: on `version` events (and on initial `GET /api/artifacts` load), upsert storyboard shapes in a clean grid row with staggered offsets.
   - The prompt bar and the `<Steps>` progress panel stay as **DOM overlays pinned over the canvas** (standard tldraw-host pattern); everything else lives on the canvas.
   - **UX change (intentional, matches plan.md demo path):** after generation the board stays visible and the 3 cards appear live; we no longer auto-navigate to the editor — clicking a card opens it.
3. Keep all existing data flow in Board: `readAgentStream` consumption (`step`/`version`/`error`/`done`), `loadItems`, brand fetch — only the rendering moves into tldraw.

**Not in this pass:** making the Editor preview itself a tldraw canvas (drag/resize of layers). The Editor keeps its layer list + Inspector + versions. plan.md's manual-editing drag/resize becomes a follow-up.

## Workstream B — AI SDK tool-loop agent

**Files:** new `lib/agent/provider.ts`, new `lib/agent/tools.ts`, rewrite of `lib/agent/workflow.ts`. `app/api/agent/route.ts` unchanged (same generator contract), `lib/agent/types.ts` unchanged.

0. **Step 0 — live probe:** one-off curl against `${META_API_BASE_URL}/chat/completions` with a `tools` array on `muse-spark-1.3` to confirm the endpoint honors OpenAI tool-calling (the current facade only ever used JSON mode). If it does not, stop and report back with the fallback (keep fixed pipeline, ship tldraw only) rather than shipping a broken loop.
1. **`lib/agent/provider.ts`** — `createOpenAICompatible({ name: 'meta', baseURL: META_API_BASE_URL, apiKey: META_API_KEY })`; export `sparkModel()` (loop driver; pass large `maxOutputTokens`). Reuse env handling from `lib/meta/config.ts`.
2. **`lib/agent/tools.ts`** — zod-typed tools wrapping the existing facade (`lib/meta/index.ts`) — no new model plumbing:
   - `create_storyboard { angle, prompt }` → `meta.storyboard` → `db.createArtifact` (v1) → emits `step` + `version` events → returns `{ artifactId, sceneCount }`.
   - `apply_patch { ops }` → validated against the run's allowed layer-id set → returns applied op count (actual `applyPatch` applied server-side after the loop).
   - `generate_image { layerId, prompt }` → `meta.image` + `persistAsset`.
   - `segment_subject { layerId, concept }` → `meta.segment` + `persistAsset`.
   - Each `execute` emits `step` events through a closed-over emitter (tool internals already mock out when `!metaLive`).
3. **`lib/agent/workflow.ts`** — keep the exported signatures (`generateStoryboards`, `refineArtifact` async generators yielding `AgentEvent`):
   - Bridge tool-callback events → the generator via a small async queue (events must stream live, not buffer until the loop ends).
   - `generateStoryboards`: `meta.planWonder` (Wonder as planner, unchanged) → `generateText({ model: sparkModel(), tools, stopWhen: stepCountIs(N), onStepFinish })` instructed to produce 3 variants (hook/product/proof angles) and to fill empty image layers (`generate_image`) and segment flagged layers (`segment_subject`). After the loop, a deterministic sweep with the existing `resolveAssets` catches anything the model missed, then version events.
   - `refineArtifact`: `meta.planWonder` (refine mode, target layers) → loop with `apply_patch`/`generate_image`/`segment_subject` scoped to target layers → `applyPatch(doc, ops, allowedSet)` → `addVersion`.
   - When `!metaLive`: bypass the loop and call the facade mocks directly (today's behavior preserved for offline tests).
4. Prompts: add a small system prompt for the loop driver in `lib/meta/prompts.ts` (tool-selection rules, angle assignment, scope enforcement); existing `storyboardSystem`/`PATCH_SPEC` stay as the tools' inner prompts.
